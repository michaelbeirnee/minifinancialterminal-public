Four ways in

One registry, four front doors.

Query the same command from REST, Python, the CLI or the web UI and get the same normalised result. A command added under backend/extensions/ appears in every one of them with no extra wiring.

01

REST API

One route per command, generated from the registry and documented at /docs.

GET /api/v1/equity/
    price/historical
    ?symbol=AAPL
02

Python

The same surface as attribute access, returning a normalised MFTObject.

mft.equity.price
   .historical(
     symbol="AAPL")
03

CLI

Menu navigation, tab completion and CSV export — stdlib only, no dependencies.

python -m cli.terminal

/equity/price/ $ quote
04

Web UI

DATA browses every command; PORTFOLIO tracks holdings; SAVED holds watchlists and alerts.

./run.sh

localhost:8000

Beyond the data layer

A research stack, not just a data feed.

Research Workbench

An expandable shell that keeps market and sector evidence separate from company evidence, requires the causal exposure bridge to be written explicitly, and freezes the joined packet into the thesis ledger.

Factor models

Market, momentum and low-volatility factors built from the universe, with per-asset OLS exposures — alpha, betas, t-stats, R² — via statsmodels.

Portfolios

A transaction log with FIFO or average-cost lot matching. Holdings are derived, never edited, so a corrected trade re-states history rather than leaving a counter wrong.

Portfolio analytics

Daily time-weighted returns with deposits neutralised, plus money-weighted XIRR; VaR in dollars; marginal risk contribution per holding; sector and country tilt; factor exposure regressed on the whole book.

Backtesting

Two engines sharing one cost model — a fast vectorized backtester and an event-driven engine with explicit cash, commission, slippage and per-fill logs. Both apply a one-bar execution lag to avoid look-ahead bias.

Backtest analysis

Parameter grid sweeps, walk-forward evaluation with rolling train/purge/test folds, benchmark-relative attribution, cost-sensitivity ladders and block-bootstrap Monte Carlo bands on terminal wealth and drawdown.

Auth & caching

JWT bearer auth with bcrypt and revocable sessions — logout kills the token server-side. A graded-TTL cache sits in front of every outbound call: 2 minutes for quotes, a week for reference data.

Architecture

A command is a decorated function.

Registering it once produces the REST route, the Python attribute, the CLI menu entry and the OpenAPI docs — which is how the platform carries a few hundred commands without a few hundred hand-written routes.

@command("/equity/price/quote", providers=("yahoo",),
         summary="Snapshot quote")
def price_quote(symbol: str,
                provider: Optional[str] = None) -> Result:
    src = resolve_provider(provider, ("yahoo",))
    return Result(
        [yahoo.quote(s) for s in norm_symbols(symbol)],
        provider=src,
    )
  • core/ — the registry, the FastAPI walker, the Python interface, cached HTTP with per-host throttles
  • providers/ — one module per data source, no command logic
  • extensions/ — the 21 command menus
  • assistant/ — a system prompt generated from the registry and four read-only tools
  • backtest/ · factors/ · portfolio/ · reports/ — the research and accounting stack
  • frontend/ — index.html, styles.css, app.js — no build step
Charts without a chart library. /charting/* emits Plotly-compatible JSON built by hand, so nothing depends on a plotting package being installed.
The assistant

A chat window that knows this codebase.

It explains concepts — what a Sharpe ratio measures, why an inverted curve gets attention — and reaches into the platform to answer with your data instead of from memory. It learns the command surface the same way every other interface does: from the registry.

ASSISTANT
you › Is the yield curve inverted, and why does that matter? ⟨ /fixedincome/government/yield_curve ⟩ ⟨ /fixedincome/spreads ⟩ mft › Slightly, at the short end… ‹answer built from the rows it just pulled›
  • The whole command index ships behind a prompt-cache breakpoint, so it is a cache read rather than ~6k fresh input tokens per message.
  • Replies stream over SSE with a chip per command as it runs — an answer that quietly ran five commands should show you which five.
  • All four tools are read-only: it can read your portfolio but never trade, edit or delete.
  • Transcripts live in the browser tab and are not persisted.
This is the only paid dependency in the stack. Leave MFT_ANTHROPIC_API_KEY unset and the tab explains that it is switched off; every data command, the backtester, the factor engine and the portfolio ledger are unaffected.
Quick start

Running in about a minute.

Verified on Python 3.14 (numpy 2.5 / pandas 2.3 / FastAPI 0.140); runs on 3.9+.

01 — INSTALL

Dependencies

pip install -r requirements.txt

No API keys to configure first — the platform runs unkeyed.

02 — SERVE

Web UI + REST

./run.sh
# http://localhost:8000

Register a user and explore. OpenAPI docs live at /docs.

03 — DRIVE IT

CLI or Python

python -m cli.terminal
python -m cli.terminal \
  "/technical/rsi --symbol SPY"

Or import mft and call the same commands in a notebook.

Docker. docker compose up -d builds and runs the whole stack on port 8000. State survives rebuilds in a shared host directory ($MFT_DATA_DIR, default ~/.5milliondollars) bind-mounted to /data. Run one server at a time — run.sh refuses to start while the container is up.
